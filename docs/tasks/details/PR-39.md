# PR-39: Production application topology controls

- Phase: production_hardening
- Owner role: coordinator
- Dependencies: PR-32, OPS-15
- Owned paths: production Compose topology, operations documentation, and this task detail

## Objective

Declare the minimum production-like application replica and resource envelope
used by the capacity plan instead of leaving scheduling behavior implicit.

## Acceptance criteria

- Each stateless application service has an explicit replica count with a
  documented override.
- CPU and memory limits/reservations are declared for each application service.
- Database and broker services are not accidentally scaled by the application
  replica setting.
- Compose rendering succeeds with explicit deployment image/config values.

## Validation

- `docker compose -f infra/deploy/docker-compose.prod.yml -f infra/deploy/docker-compose.staging.yml config`
- `git diff --check`

## Current increment

Added a shared application deployment envelope: three replicas by default,
four CPU/eight GiB limits, and one CPU/two GiB reservations, all explicitly
overridable through deployment variables. The envelope is attached only to
Accounts, Expense Core, Notifications, and BFF in the production base file;
stateful staging services are not scaled by it.
