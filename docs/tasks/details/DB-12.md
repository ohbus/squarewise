# DB-12: Add performance, contention, and capacity tests

Build repeatable scenarios for realistic operation mix, hot groups, deep
pagination, idempotency contention, outbox pressure, pool exhaustion, reader
lag/failure, writer protection, and recovery. Establish provisional p95/p99,
error, connection, and lag budgets and distinguish local from production proof.

Acceptance includes machine-readable results, repeatable commands, baseline
comparison, and documented unresolved environment limitations.

## Concrete code targets

- Extend `tests/performance/` scenarios and existing k6/load scripts for Expense Core search, group reads, expense/settlement commands, outbox, and BFF fanout.
- Extend `PostgresExpenseIdempotencyConcurrencyTest`, `PostgresMembershipMutationRaceTest`, `PostgresSettlementReconciliationTest`, and group concurrency tests with route/pool evidence.
- Add reader lag/outage and pool-exhaustion fixtures to `tests/acceptance/` or the approved integration-test harness.
- Record result format and budgets in `docs/quality/acceptance.md` and `docs/operations/` without treating local Docker as production capacity proof.

## Current increment

`tests/performance/cqrs-replica-smoke.sh` verifies the merged local topology's
streaming state, replica recovery mode, replay LSN, and authenticated route
telemetry. It emits machine-readable key/value output and deliberately labels
unauthenticated telemetry as `not_checked`; it does not claim production
capacity, failover, or durability evidence. Contention, pool-exhaustion,
failure-injection, and baseline budget scenarios remain open.

## Capacity smoke evidence (2026-09-22)

`REQUESTS=100 CONCURRENCY=10 sh tests/performance/capacity-smoke.sh` completed
100/100 readiness requests with zero failures in 2 seconds (50 requests per
second) against the local BFF. This is a repeatable local readiness baseline,
not a production p95/p99 or capacity budget; authenticated business-operation
mix, contention, pool exhaustion, and baseline comparison remain open.
