# QA-03: Real multi-service acceptance test scenarios

Implement executable end-to-end acceptance scenarios in `tests/acceptance/` exercising the running services or reporting clear blocked status when unavailable.

## Acceptance criteria

- `tests/acceptance/runner.py` executes real HTTP scenarios:
  - `QA-GROUP-EXPENSE-SETTLEMENT`: Create group, create expense with payers and allocations, fetch balances, record settlement, and verify balance state.
  - `QA-OFFLINE-REPLAY`: Fetch snapshot (`GET /sync/snapshot`) and changes (`GET /sync/changes`) verifying monotonically increasing group revisions and items.
  - `QA-WEBSOCKET-RESYNC`: Query GraphQL BFF endpoint `/graphql` for `{ groups { id name } }` or verify live update fanout.
- Scenarios report `passed` when services are reachable and `blocked` when services are offline (non-zero only with `--require-services`).
- Produces machine-readable JSON acceptance report in `build/reports/acceptance/qa-01.json`.

## Implementation details

- **Harness Updates (`tests/acceptance/runner.py`)**:
  - Implemented HTTP probing for BFF (`http://localhost:8080/actuator/health`) and Expense Core (`http://localhost:8082/actuator/health`).
  - Implemented real scenario execution against running REST and GraphQL APIs.
  - Generates machine-readable report at `build/reports/acceptance/qa-01.json`.
  - Added CLI flags `--bff-url`, `--expense-core-url`, `--timeout`, and `--report-path`.
- **Harness Unit Tests (`tests/acceptance/test_runner.py`)**:
  - 9 automated unit tests verifying argument parsing, in-memory mock server responses for scenarios, offline blocking behavior, and failure code reporting.
