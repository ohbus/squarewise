## Current implementation increment

`SearchController` now performs writer-based membership authorization first,
then scopes only `expense.search` and `expense.search.export` as eventual,
reader-eligible operations. The optional replica Compose override enables the
Expense Core routed datasource with the writer at `postgres-db` and the search
reader at `postgres-replica-db`. The repository now applies description,
currency, category, and UUID keyset cursor filtering in SQL, returns a scalar
projection, and fetches one extra row for bounded `hasMore` detection. The
existing response/domain layer still owns totals and CSV formatting.

## Route evidence (2026-09-22)

`SearchControllerTest` now records the execution context at the search adapter
boundary and asserts `expense.search` is a `QUERY` with `EVENTUAL` consistency
and explicit reader eligibility. Membership authorization executes before this
context is entered. The test does not claim production replica availability;
live Compose smoke and PostgreSQL plan/load evidence remain separate open
items.

## Query-plan evidence (2026-09-22)

`tests/performance/expense-search-plan.sh` runs
`EXPLAIN (ANALYZE, BUFFERS, SETTINGS)` on the replica for the bounded search
projection and requires an `Index Scan using expenses_group_idx`. The local
empty-group probe used 4 shared-buffer hits and 0.068 ms execution time; this
is repeatable local plan evidence, not a populated production workload or
capacity baseline.

A populated lifecycle group probe (`GROUP_ID=01a0c619-f842-7f95-9406-354abd9d2e47`)
also used the required `expenses_group_idx` scan, examined one filtered row,
and completed in 0.052 ms with 5 shared-buffer hits. The query returned no
matching `dinner` description, so this remains plan evidence rather than a
representative result-volume benchmark.
