# DB-01: Register CQRS data-access workstream and operation catalog

## Objective

Create the authoritative inventory needed before routing any SQL operation.

## Scope

Inventory every Accounts, Expense Core, and Notifications repository/store
method, native query, transaction boundary, lock/claim, mutation, expected
cardinality, pagination, consistency requirement, route, timeout, owner, and
consumer. Include Flyway, reconciliation SQL, scheduled workers, tests, and
the BFF propagation points. Record current gaps and a migration order.

## Acceptance criteria

- A versioned catalog covers every persistence operation and identifies writer-only behavior.
- Each catalog entry has an owner, target path, dependency, and verification command.
- Architecture validation fails for uncatalogued direct datasource/repository access.
- Registry, board, implementation plan, and task details agree on the dependency DAG.

## Evidence

Catalog diff, validator output, `./gradlew.bat test --no-daemon`, contract validation, and `git diff --check`.
