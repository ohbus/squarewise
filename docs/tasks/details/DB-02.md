# DB-02: Define CQRS data-access architecture and consistency contracts

Define the technical contract for command/query classification, `STRONG`,
`SESSION`, `BOUNDED_STALENESS`, and `EVENTUAL` reads, causal watermarks,
reader fallback, deadlines, retry rules, route errors, and freshness semantics.

Acceptance requires updated architecture/technology/operations documentation,
explicit writer-only rules for locks, claims, idempotency, authorization,
migrations, and financial reads, and reviewable examples for one command,
one strong read, one session read, and one eventual read. Contract validation,
link checks, registry validation, and `git diff --check` are required.
