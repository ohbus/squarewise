# PR-42: Bound RabbitMQ transient redelivery

- Phase: production_hardening
- Owner role: coordinator
- Dependencies: PR-19, PR-36
- Owned paths: Notifications Rabbit listeners/tests, messaging operations documentation, and this task detail

## Objective

Prevent transient consumer failures from requeueing forever while retaining a
bounded retry opportunity before dead-lettering.

## Acceptance criteria

- A first transient consumer failure is requeued once.
- A redelivered transient failure is rejected without requeue and reaches the
  configured DLQ.
- Malformed/permanent messages remain non-requeued.
- Notification and auth-email listener tests cover both branches.

## Validation

- `git diff --check`

## Current increment

Both notification and auth-email listeners now requeue a transient failure only
when RabbitMQ has not marked the delivery as redelivered; a repeated transient
failure is rejected without requeue and therefore follows the configured DLX
route. Malformed/permanent failures remain non-requeued. The full Notifications
test suite passed, including notification and auth-email transient-redelivery
coverage.
Production-like retry timing, DLQ alerting, and broker-failure evidence remain
operational release gates.
