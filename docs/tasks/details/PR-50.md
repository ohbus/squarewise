# PR-50: Remediate six independent PR #19 findings

- Phase: production_hardening
- Owner: coordinator (`/root`)
- Dependencies: PR-45, DB-15, CORE-31, PR-30, PR-49
- Owned paths: recurring membership generation, writer routing, Expense Core authorization, BFF subscriptions/fanout, focused tests, and this task record

## Objective

Close six independently identified correctness, authorization, resource-lifetime,
and dead-code findings in the pushed PR #19 implementation without changing the
public API contracts.

## Decisions

- Recurring generation loads at most `MAX_PARTICIPANTS + 1` active memberships
  after each schedule lock; it does not reuse a pre-lock bulk snapshot or the
  authorization cache.
- Financial participant validation is explicit for internal writes
  (`validateParticipants = true`); actor-backed requests keep the default
  validation, and idempotency-key prefixes are not security gates.
- Financial balances and settlement suggestions are writer-bound and bypass the
  membership cache so replica lag cannot serve stale financial state.
- Export-request admission resolves the subject profile from the writer-backed
  repository and requires the account reference validator; profile cache hits
  cannot bypass deletion checks.
- Membership authorization queries temporarily establish a strong writer route
  when called from an eventual-reader context.
- Reactive GraphQL subscriptions compose their revocation signal with a TTL
  signal; `Flux.using` cleanup removes all indexes and sinks.
- The unused imperative `LiveUpdate` queue and `deliveredQueues` result field are
  deleted. The bounded per-subscription reactive invalidation channel remains.

## Validation

The focused and full Gradle test commands in the registry passed. The
implementation is recorded in commits `997beb79`, `a7f62525`, and `3db58ebf`.

## Implementation notes

- Recurring due processing no longer preloads a cross-schedule membership map;
  each locked schedule performs a bounded writer query (`MAX_PARTICIPANTS + 1`)
  and explicitly requests participant validation for the generated expense.
- `EntityReferenceValidator` and `JpaGroupStore` force writer contexts for
  membership/group authorization, including nested reader-scoped calls.
- Unknown named writers now raise `PLATFORM_CONFIGURATION_INVALID`.
- GraphQL subscription streams combine revocation and expiry signals, and the
  old imperative `LiveUpdate` queue/result accounting was deleted. BFF scheduling
  also drains a due-time priority queue, bounded to 1,000 expired entries per
  sweep, for subscriptions that never attach to a stream.
- Existing staging volumes now have an explicit, idempotent PostgreSQL
  role/ownership reconciliation command mounted by the staging Compose
  overlay; it uses the admin password and moves public objects without unsafe
  `REASSIGN OWNED`; it does not rewrite or upgrade the retired Flyway chains.
- Notification preference invalidation-marker cleanup is throttled with an
  atomic one-second gate, and delivery tests assert the exact `SKIPPED` status
  and notification identifier for terminal suppression paths.
- BFF expiry sweeping is bounded by the configured inspection budget, including
  stale due entries, rather than scanning unrelated live subscriptions. Focused
  tests cover deterministic index cleanup, concurrent admission, per-subscription
  delivery, removal revocation, queue overflow, and stale-queue compaction.
- Architecture inventories now match the writer-bound balance path and the
  actual profile endpoint names.

## Known limitations

This is static/local implementation evidence. Hosted replica lag, production
capacity, deployed multi-writer topology, and the existing-volume rebuild/
baseline and rollback drill are not reproduced by local tests. The
role/ownership command must be run by an operator with PostgreSQL administrative
access before rotating staging credentials.
