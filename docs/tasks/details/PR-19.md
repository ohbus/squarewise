# PR-19: Messaging retry, dead-letter, and poison-message handling

- Phase: production_hardening
- Owner role: coordinator
- Dependencies: MSG-01, MSG-02, PR-17
- Owned paths: `app/expense-core/src/main/kotlin/com/subhrodip/squarewise/expensecore/messaging/`, `app/notifications/src/main/kotlin/com/subhrodip/squarewise/notifications/consumer/`, focused messaging tests, and this task detail

## Objective

Make broker delivery fail closed and operationally recoverable: transient
failures retry with bounded attempts, malformed/poison messages are isolated in
dead-letter queues, and successful consumer effects are acknowledged only after
transactional processing.

## Acceptance criteria

- Notification and auth-email queues are durable and route rejected poison
  messages to explicit dead-letter exchanges/queues.
- Outbox retry and parking remain bounded and observable.
- Production profiles cannot silently select the in-memory broker publisher.
- Listener tests cover malformed envelopes, transient requeue, permanent reject,
  and duplicate delivery.

## Current increment

Notification and auth-email queues now declare durable dead-letter routing with
separate operator queues. The expense-core in-memory broker fallback is
profile-excluded from `production` and `staging`, so deployed profiles must
provide an explicit publisher. Notification listener tests cover malformed
notification envelopes, transient requeue, duplicate acknowledgement, and
auth-email malformed-envelope rejection; the full Notifications suite passes.
The live local broker initially contained incompatible legacy queues, so the
release now uses versioned `.v2` defaults without deleting or redeclaring the
legacy queues. Rebuilt Notifications declared both `.v2` source queues and
DLQs with the DLX argument. A malformed event published to the local events
exchange was rejected into `squarewise.notifications.v2.dlq` (one message).
Production-like retry, alerting, and controlled legacy replay evidence remain
open; the drain/replay procedure is documented in
`docs/operations/messaging-topology-migration.md`.

The Rabbit publisher now waits for a broker publisher confirm before the
transactional outbox row is acknowledged as `PUBLISHED`; publisher confirms
are enabled and unroutable messages are mandatory. Focused publisher/outbox
tests passed. The local chaos E2E verified `PENDING` during a paused RabbitMQ
broker, followed by recovery to `PUBLISHED` and downstream Notifications
delivery.
