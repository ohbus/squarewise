# PR-27: Notification fail-closed delivery policy

- Phase: production_hardening
- Owner role: coordinator
- Dependencies: PR-19, NOT-10
- Owned paths: Notifications delivery/consumer code, focused tests, and this task detail

## Objective

Prevent notification delivery from overriding user privacy choices or masking
missing recipient identity when preference or profile dependencies fail.

## Acceptance criteria

- Preference lookup failure suppresses delivery and is observable, never treated
  as opt-in.
- Missing or blank recipient identity is rejected or parked, never replaced with
  a synthetic address.
- Delivery rate limiting is enforced on the consumer path before dispatch.
- Tests cover preference failure, missing recipient, opt-out, and rate-limit
  behavior without acknowledging unsafe delivery as success.

## Validation

- `./gradlew.bat :app:notifications:test --rerun-tasks --no-daemon`
- `git diff --check`

## Current increment

The consumer now suppresses delivery when preference lookup fails or returns no
preference, requires an explicit email-shaped recipient instead of synthesizing
one, and applies a Spring-wired per-recipient rate limiter before dispatch.
Focused consumer tests cover preference failure, missing recipients, opt-out,
and rate limiting; the full Notifications suite passes.
