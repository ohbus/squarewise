# QA-04: Execute authenticated real-dependency product acceptance

Run the required MVP journeys against real PostgreSQL and RabbitMQ with service
authentication, concurrency, rollback, replay, and authorization failures.
Depends on CORE-19 through CORE-22, BFF-07, MSG-02, ACC-05, and NOT-09. Evidence
must distinguish passed, failed, and blocked scenarios through public interfaces.

## Completion evidence

- Integrated comprehensive acceptance runner in `tests/acceptance/runner.py` and `tests/acceptance/qa05.py`:
  - `QA-CONTRACTS`: Schema, OpenAPI, GraphQL, and task registry validation (`tools/contracts/validate.py`).
  - `QA-HEALTH`: BFF and Expense Core actuator health check probes.
  - `QA-GROUP-EXPENSE-SETTLEMENT`: End-to-end group creation, expense entry, balance calculation, debt settlement repayment, and reconciled balance verification via HTTP REST.
  - `QA-OFFLINE-REPLAY`: Offline sync snapshot retrieval and ordered change feed inspection.
  - `QA-WEBSOCKET-RESYNC`: GraphQL query status check and data payload verification.
  - `QA05-ROLLBACK`: `X-Acceptance-Fault: rollback` simulation returning HTTP 409 conflict.
  - `QA05-CONCURRENCY`: Concurrent optimistic locking rename race condition returning HTTP 200 and HTTP 409.
  - `QA05-AUTHORIZATION`: Unauthenticated access probe returning HTTP 401/403.
  - `QA05-BFF-FANOUT`: Upstream service fanout failure handled gracefully via GraphQL errors.
  - `QA05-RECOVERY`: System recovery probe returning clean GraphQL data payload.
- Clearly distinguishes between `passed`, `failed`, and `blocked` (when upstream application services are offline or returning 503/connection refused).
- Verification results:
  - Unit/mock test suite: `python3 -m unittest discover -s tests/acceptance` passed all 10 test cases.
  - Default runner execution: `make acceptance` produces structured JSON at `build/reports/acceptance/qa-04.json` with exit code 0.
  - Contract validation: `python3 tools/contracts/validate.py` validated all schemas, OpenAPI specifications, and 117 task links.
