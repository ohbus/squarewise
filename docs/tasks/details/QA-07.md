# QA-07: Exhaustive public-interface integration coverage

## Objective

Create and execute a contract-driven coverage matrix for every implemented REST
operation, GraphQL query/mutation/subscription, and WebSocket lifecycle. The
matrix must distinguish unit, adapter/controller, persistence, live integration,
and end-to-end evidence and must not treat syntactic contract validation as
proof of semantic route coverage.

## Acceptance criteria

1. Every implemented public operation has a matrix row linked to its contract,
   implementation, and executable test evidence.
2. Each REST and GraphQL operation covers applicable success, validation,
   authentication, authorization, not-found, conflict, idempotency,
   pagination/boundary, malformed-input, timeout, dependency-failure, and
   persistence/side-effect cases.
3. GraphQL HTTP, WebSocket handshake, subscription filtering, reconnect/error,
   authorization, queue, expiry, and broker-recovery behavior are exercised.
4. Concurrent updates, stale revisions, duplicate replay, outbox delivery,
   notification deduplication, and recovery are verified through public
   interfaces where the behavior is externally observable.
5. OpenAPI path structure is semantically validated and agrees with controller
   routes; the QA-05 deterministic harness no longer disagrees with its live
   rollback classification.
6. Quality, API, operations, task tracker, and progress documentation records
   exact commands, evidence paths, runtime limitations, and uncovered cases.

deployment rollback remain environment-dependent and must not be represented
as locally proven by this task.

HTTP 406 with an intentionally bodyless response, avoiding a second content-
negotiation failure while preserving RFC 7807 responses for negotiable errors.
The edge suite covers both this 406 case and `maxRows=0` as HTTP 400; the
standalone controller regression and live check both pass.

The latest `make e2e-all` execution passed all four live suites: product
