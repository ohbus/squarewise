# QA-11: Publish JVM coverage information

## Objective

Publish the repository's aggregate JVM line-coverage report for `master` and
master-targeting pull requests without enforcing a threshold or merge rule.
Same-repository runs publish Cobertura XML through GitHub Code Quality. Fork
pull requests retain a downloadable, attested coverage artifact where GitHub
permissions allow, while the Code Quality upload is skipped because fork
tokens cannot write that result.

## Acceptance criteria

- A full Gradle JaCoCo run produces one deterministic aggregate Cobertura XML
  report for the JVM modules on `master`, internal pull requests, and fork pull
  requests targeting `master`.
- `master` and same-repository pull requests upload the Cobertura report to
  GitHub Code Quality with least-privilege `code-quality: write` permissions.
- Fork pull requests do not use `pull_request_target` or secrets; their
  coverage artifact remains downloadable and the unsupported Code Quality upload
  is explicitly skipped.
- The coverage artifact is attested when the event token can write attestations.
- Coverage remains informational: no minimum, drop threshold, ruleset, or
  required status check is added.
- The converter and workflow have focused local validation and typed Python
  tooling evidence.

## Known limitations

The initial report covers JVM JaCoCo output only. Python coverage is not added
until the repository has a published Python coverage contract and test scope.
GitHub's Code Quality upload action cannot publish results from fork pull
requests with the downgraded token, so those runs intentionally retain the
artifact instead.
