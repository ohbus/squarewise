# PR-46: Durable settlement recording idempotency

- Phase: production_hardening
- Owner role: coordinator
- Dependencies: PR-17, PR-26
- Owned paths: Expense Core settlement service/store/controller, migration, tests, contracts, and task evidence

## Objective

Extend durable replay protection to settlement recording at the public REST
boundary, scoped by group, authenticated actor, and operation.

## Acceptance criteria

- Settlement recording requires a bounded idempotency key.
- Same-key same-payload replay returns the original settlement without new
  postings.
- Same-key different-payload requests fail with conflict.
- The claim and settlement postings commit atomically under the group lock.
- Public controller tests cover replay and conflict behavior.

## Current increment

Settlement recording now requires a bounded `Idempotency-Key` and derives a
stable settlement identity from group, actor, and key. Replaying the same
payload returns the existing settlement without new postings; changing the
participants or amount for the same identity raises a conflict. The OpenAPI
contract was updated and settlement-focused Expense Core tests passed,
including altered-payload replay rejection. The full Expense Core test suite
also passed. Production PostgreSQL concurrent settlement evidence remains an
operational follow-up. `SettlementControllerTest` now proves same-key HTTP
replay returns the same settlement and altered payloads return conflict.
