# DB-11: Add database observability and slow-query governance

Standardize operation names and emit route, pool, duration, acquisition,
transaction, rows, timeout, lock, deadlock, retry, and replica-lag telemetry.
Add sanitized tracing and operational procedures for `pg_stat_statements`,
controlled `EXPLAIN`, wait events, bloat, autovacuum, and index usage.

Acceptance proves low-cardinality metrics, no sensitive SQL parameters, useful
dashboards/alerts, and a remediation record containing baseline, hypothesis,
plan, trade-offs, and rollback.

## Concrete code targets

- Add datasource/pool/route timers and counters in `libs/db` and common tags through `libs/observability`.
- Instrument the existing JPA stores and native-query paths, especially `JpaExpenseStore`, `JpaGroupStore`, `JpaOutboxStore`, `JpaSynchronizationStore`, Accounts auth repositories, and Notifications inbox/deduplication stores.
- Update `infra/observability/prometheus.yml`, alert rules, Grafana provisioning, and operations documentation.
- Add a query-operation catalog and sanitized logging tests; never log SQL parameters, tokens, emails, invitation secrets, or financial payloads.

## Current increment

`DbTelemetry` now records validated operation route, bounded writer fallback,
reader failure, and replay-lag signals without SQL text or request payloads.
The routed datasource and reader health scheduler share the instrumentation,
and no-registry snapshots remain available for tests and diagnostics. Duration,
pool-acquisition, lock/deadlock metrics, dashboards, and alert rules remain
open for the next increment.
Prometheus alerts and `docs/operations/cqrs-replica.md` now cover replay lag,

lock/deadlock metrics, and dashboard panels remain open.

## Pool acquisition increment (2026-09-22)

`DbTelemetry` now records pool-acquisition count and total milliseconds in its
diagnostic snapshot and emits a Micrometer timer tagged only by validated
operation and pool (`writer` or `reader`). `DbRoutingDataSource` measures
writer and named-reader acquisition around the existing route instrumentation;
SQL text, parameters, tokens, and payloads are not included. Observability
tests cover the aggregate timing snapshot. Lock/deadlock metrics, dashboards,
and production query-plan governance remain open.

`DbTelemetry` also exposes low-cardinality lock-wait and deadlock counters for
store/query instrumentation to report when those database signals are
observed. Snapshot and Micrometer counter coverage is tested; wiring every
JPA/native query path and dashboard visualization remains open.

The Squarewise overview dashboard now includes reader replay lag, writer
fallback rate, pool-acquisition p95, and lock/deadlock signal panels. Panel
queries use only service, operation, pool, and reader labels; Grafana JSON
validation passed.

## Query-duration governance increment (2026-09-22)

`DbTelemetry.queryDuration` now records bounded query count, total duration,
slow-query count, and Micrometer duration/counter metrics using only stable
operation and route labels. The threshold is validated and configurable; the
telemetry unit test proves slow-query classification without SQL text,
parameters, tokens, or payloads. Store-level invocation and production
baseline evidence remain open.

Expense Core `SearchController` now measures both bounded search and CSV
export query blocks through the same API using stable operation names and an
`approved-query` route category. The focused search tests and observability
suite pass; datasource-selected route metrics remain authoritative for actual
reader-versus-writer routing.

Accounts profile lookup/batch reads and Notifications historical inbox reads
now use the same measurement wrapper and stable `approved-query` category.
Focused `ProfileControllerTest` and `InboxControllerTest` suites pass.
