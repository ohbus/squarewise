# DB-13: Add optional replica topology to infrastructure

The local replica topology implementation is complete and verified with
standalone/merged Compose validation, live streaming checks, authenticated
E2E, and disconnect/recovery drills. Production promotion and restore remain
operational gates under DB-16.

Add local and production-like PostgreSQL streaming-replica topology, service
private credentials, health probes, reader endpoints, replication settings,
and deployment overlays. Keep the topology disabled unless explicitly enabled.

Acceptance validates standalone and merged Compose/deployment configuration,
replication health, migration-on-writer behavior, secret examples, and clear
documentation that single-database mode is not replica evidence.

## Concrete code targets

- Update `infra/local/docker-compose.yml`, local overrides, `infra/deploy/docker-compose.staging.yml`, and `infra/deploy/docker-compose.prod.yml` with optional PostgreSQL reader topology and network aliases.
- Update `infra/local/init-databases.sql`, environment examples, health checks, and service URL variables; do not duplicate version authorities.
- Add replica health/replay diagnostics to `infra/observability/` and operational quickstart/topology docs.
- Add Compose config validation and a controlled replication smoke procedure; preserve current single-writer defaults.

## Local smoke procedure

Run `docker compose -f infra/local/docker-compose.yml -f
infra/local/docker-compose.replica.yml up -d postgres postgres-replica`, then
verify `pg_stat_replication` on `local-postgres-1` reports the replica in
`streaming` state and `pg_is_in_recovery()` is true on
`local-postgres-replica-1`. Existing PostgreSQL volumes do not replay init
scripts; create or rotate the local `squarewise_replica` role explicitly before
the first base backup. Do not delete volumes as part of routine verification.
