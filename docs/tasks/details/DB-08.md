Implementation is complete: profile command/query ports, writer-only
authentication state, bounded approved reads, route/telemetry tests, and
authenticated replica E2E are verified. Production SLO/failover gates remain
with DB-14/DB-16.

Keep credential/session state, rate limits, token consumption, export/deletion
transitions, and auth-email outbox on the writer. Introduce explicit query ports
for only approved profile/preferences reads, with causal follow-up support.

writer fallback, and all existing Accounts authentication/persistence suites.

## Current implementation increment

`ProfileController` now scopes only public profile-by-ID and bounded batch
lookup as eventual, reader-eligible operations. The `/me` read may provision a
profile and therefore remains writer-bound. Accounts has named writer/profile
reader configuration, while authentication, sessions, rate limits, and
profile mutation remain unchanged on the writer.

## Route evidence (2026-09-22)

`ProfileControllerTest` now records the profile adapter context and asserts
`profile.lookup` is a `QUERY` with `EVENTUAL` consistency and explicit reader
eligibility. The `/me` path remains outside that scope and retains the
writer-default behavior. Replica outage and read-after-write integration

reads from writer-side update/deletion transitions; `ProfileStore` remains a
compatibility facade for existing adapters.
