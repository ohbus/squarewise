# DB-03: Implement shared `libs/db` routing and execution-context kernel

Implement typed route targets, operation kinds, execution context, read policy,
transaction-bound route selection, and guards that reject reader use from
write/locking/claim transactions. Keep entities, business repositories,
migrations, and service policy out of the library.

Acceptance requires unit tests for route selection, nested transactions,
context cleanup, illegal route changes, deadlines, and writer-only operations;
all consuming applications compile and the architecture boundary check passes.

## Concrete code targets

- Create the `libs/db/src/main/kotlin/.../db/{config,routing,policy}` source tree; `libs/db` currently has no Kotlin source.
- Update `libs/db/build.gradle.kts` to expose only technical dependencies and add `src/test` coverage.
- Add the dependency to `app/accounts/build.gradle.kts`, `app/expense-core/build.gradle.kts`, and `app/notifications/build.gradle.kts`; do not add it to `app/bff`.
- Replace direct repository access in `JpaGroupStore`, `JpaExpenseStore`, `JpaSettlementStore`, `JpaSynchronizationStore`, `JpaSearchStore`, `JpaOutboxStore`, Accounts JPA stores/services, and Notifications JPA stores only after the route port is available.
- Add route assertions to existing focused tests under each application `src/test/kotlin` tree.

## Implementation note (2026-09-22)

`DbRoutingDataSource.connection` now invokes `DbRouteGuard` before honoring an
explicit route, closing the bypass where a command or strong query could request
a reader directly. `DbRoutingDataSourceTest` covers rejection for writer-only
contexts and successful acquisition for an approved eventual query. The shared
library test suite passes; nested context restoration and reader health behavior
remain covered by the existing routing/health tests.

The task is complete: the full repository regression and diff validation also
pass, and no application selects a datasource directly.
